## Детали

- [ ] #1 Добавить юз-кейс/e2e тесты (сейчас межмодульные сценарии вроде «ротация PAK → старый ключ на widget-эндпоинте не работает» покрыты только unit-тестами)
- [ ] Переделать создание структур - все структуры должны создаваться в одном месте - через методы new\build\builder, для этого во все добавить не публичное zero-size поле ()
- [ ] Стили - привести всё к одному стилю и единому источнику правды
- [ ] Supervisor - running platforms останавливаются через handle.abort(), исследовать возможность их остановки через CancelationToken
- [ ] Переделать `ActionExecutor`: сейчас это монолит со встроенной twitch-логикой (`ensure_user`, `send_chat_message`).
      `ActionExecutor` — терминальный консьюмер шины B, оркестрирует выполнение без знания платформ;
      `PlatformActionService` — матчит платформу события/экшена и выбирает исполнителя для неё;
      `PlatformActionExecutor` — по одному на платформу, реально ходит в API платформы и возвращает результат экшену.
- [ ] Нужно добавить flow проверки websocket клиента:
      В админке нужен статус - есть ли сейчас активные док панель и виджет
      В док панели нужен статус - есть ли сейчас активный виджет
- [ ] редактирование действий и правил надо переделать, сделать по аналогии со streamerbot (понадобится создать какую-то очередь супер-действий)
- [ ] Правила/награды: Создание наград на Twitch через API (`POST /helix/channel_points/custom_rewards`), требует `channel:manage:redemptions`
- [ ] Правила/награды: Автофулфилл редимпшенов (`PATCH .../custom_rewards/redemptions`)
- [ ] Правила/движок: Событийный поток наружу (WS/оверлей) — спроектировать отдельно от шины B, когда понадобится (напр., как новые экшены с собственной шиной; сейчас виджет уже читает очередь через `/wapi/queue`)
- [ ] Правила/движок: Новые матчеры и условия правил (кроме `MessageContains`/`RewardId`), кулдауны и лимиты на юзера, порог стоимости награды
- [ ] Правила/движок: Плагины экшенов без кода (скрипты/UI-редактор)
