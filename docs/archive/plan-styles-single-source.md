# Единый источник стилей фронтенда

Статус: **выполнен** (2026-08-24). Пункт бэклога #3: «Стили - привести всё к одному стилю
и единому источнику правды».

Дата: 2026-08-24

## Контекст (текущее состояние)

Слои:

- `styles/theme.css` — токены (oklch, светлая/тёмная темы) + базовые стили элементов;
  импортируется в корневом layout, грузится на всех страницах. Сюда же свалены
  `--widget-*` токены, нужные только оверлею.
- `styles/panel.css` — глобальные классы и **селекторы элементов** (`table`, `th`, `td`)
  для зоны `(panels)`; сюда утекают переопределения внутренностей ui-kit
  (`.actions-cell .btn`, `.auth-card .btn--twitch`).
- `styles/site.css` — навигация сайта, бренд, бумажная текстура.
- `styles/widget.css` — прозрачный фон для OBS.
- `packages/ui-kit` — 15 компонентов со scoped-стилями (настоящая дизайн-система).
- 22 scoped `<style>` блока в компонентах приложения.

## Найденные проблемы

1. **`.section-hint`** определён только глобально в panel.css, но используется 9
   админскими компонентами — работает исключительно потому, что panel.css глобальный.
   Правильное место — сам компонент `Section` из ui-kit.
2. **`.table-wrap` продублирован** дословно: panel.css и ui-kit `TableWrap.svelte`.
3. **Селекторы элементов `table/th/td`** в panel.css протекают во все таблицы зоны
   `(panels)`; док-панель зависит от этого утечки и добавляет свои scoped-хвосты
   (`.th-actions`) — смешанная модель «где-то глобально, где-то локально».
4. **`.inline-form` задублирован**: глобально в panel.css + копия в scoped-стилях докпанели.
5. **Шрифты несогласованы**: body в theme.css — Archivo, panel.css переопределяет на Inter,
   виджет — снова Inter; заголовки Archivo. Политика не зафиксирована токенами.
6. **Глобальные переопределения внутренностей ui-kit**: `.auth-card .btn--twitch`,
   `.actions-cell .btn` в panel.css ломают инкапсуляцию компонентов пакета.
7. **Split-brain у SiteNav**: часть стилей навигации живёт глобально в site.css,
   часть — scoped в самом компоненте.
8. **`--widget-*` токены** лежат в theme.css и грузятся на всех страницах, хотя нужны
   только оверлею.

Единственный настоящий источник правды сейчас — токены theme.css + scoped-стили ui-kit.
Всё остальное тянуть оттуда.

## Принцип целевого состояния

- Токены и базовые элементы — только theme.css (+ шрифтовые токены).
- Всё, что относится к компоненту, — scoped внутри компонента или ui-kit.
- Глобальные файлы площадок (`panel.css`, `site.css`, `widget.css`) либо пустеют,
  либо содержат только то, что нельзя выразить компонентом.
- Никаких глобальных селекторов внутрь чужих компонентов (`ui-kit`-классы из panel.css).

## План

### Шаг 1. Шрифтовые токены

В `theme.css :root`: `--font-heading: "Archivo", ...`, `--font-body: "Inter", ...`,
`--font-mono: "IBM Plex Mono", ...`; заменить все хардкоды ("Archivo"/"Inter"/"IBM Plex Mono")
в theme/panel/site/widget.css и scoped-блоках на токены. Body везде `--font-body`
(панели перестают быть исключением).

### Шаг 2. Section.hint в ui-kit

`Section.svelte` получает опциональный `hint` prop, рендерящий подсказку со scoped-стилем
(визуально как нынешний .section-hint). Обновить 9 мест использования
(`<Section hint="...">` вместо голого `<p class="section-hint">`). Удалить класс из panel.css.

### Шаг 3. Таблицы в TableWrap

Перенести стили `table-wrap/table/th/td/tr:last-child` из panel.css в scoped-стили
TableWrap (обернуть таблицу через сниппет-проп или `:global` внутри обёртки — выбрать
по месту). Докпанель оставляет себе только специфику (`.th-actions`, `.empty-row`).
Из panel.css таблицные правила удалить.

### Шаг 4. Разбор panel.css

- `.visually-hidden` → в theme.css как единственная глобальная утилита (нужен вне панелей).
- `.inline-form` оставить одной копией в panel.css, дубль из докпанели удалить;
  `.form-actions`, `.mono`, `.loading` — ревизия: используются? мигрировать к владельцам.
- Переопределения `.btn--twitch`/`.actions-cell .btn` убрать: размер твич-кнопки —
  в AuthCard/ui-kit, отступ кнопок в ячейке действий — в scoped-стилях карточек.
- Итог шага: panel.css либо пустой (файл удалить), либо ≤10 строк действительно
  площадочных правил.

### Шаг 5. SiteNav и site.css

Правила `.site-nav*`, `.brand*`, `.nav-link`, `.theme-toggle` переехать в scoped-стили
SiteNav.svelte; в site.css остаётся `.paper` (переезжает в `(site)/+layout.svelte` scoped,
если не нужен глобально). Файл site.css удалить, если опустел.

### Шаг 6. Изоляция widget-токенов

Блок `--widget-*` переехать из theme.css в widget.css (грузится только зоной `(widgets)`).
Проверить, что оверлей не использует общие токены тем наоборот (светлая/тёмная ему безразличны).

## Осознанно вне скоупа

- Визуальный редизайн: только консолидация, пиксели не меняются (кроме случая,
  когда панели получат Inter вместо текущего случайного микса — это и есть фикс бага).
- Перевод ui-kit на CSS-модули/Tailwind/что-либо ещё — стек не меняем.

## Шаг 7. Линт для отслеживания стилей и токенов

Культура в репо уже есть: кастомное eslint-правило `no-color-literals`
(packages/custom-eslint-rules) запрещает цветовые литералы в `<style>` блоков .svelte,
на бэке — ast-grep правило max-handler-lines. Развиваем в ту же сторону:

1. **`no-font-literals`** — соседнее правило в custom-eslint-rules: запрещает
   хардкод `font-family` ("Inter"/"Archivo"/...) в `<style>` блоках, требует
   `var(--font-*)`. Включается после шага 1 (иначе все падают сразу).
2. **stylelint** для глобальных `styles/*.css`, которые eslint не видит:
   - `declaration-property-value-allowed-list` на цветовые свойства → только `var(--*)`
     (theme.css в игноре — там токены определяются);
   - разрешённый список `font-family`;
   - синтаксис standard, конфиг `stylelint.config.js`, запуск в `lint` скрипте фронта.
3. **max-lines для .svelte** — встроенное eslint-правило `max-lines` (soft-cap ~300,
   с `skipBlankLines`); служит сторожем против повторного разрастания компонентов
   (см. шаг 8). Сначала фиксируем текущий разумный уровень, новые крупные файлы
   больше не появляются.

## Шаг 8. Разбиение крупных компонентов

Аудит размеров (top): dock/+page 560 строк, widgets/roulette 446,
RulesSection 384, RaritiesCard 332, ActionsSection 257, AdminsCard 254,
RouletteSlotsCard 249.

Правило разбиения: компонент/страница смешивает ≥2 ответственности → выделяем
презентационную часть; страница сохраняет данные/ws/polling. Не дробим ради дробления.

- **dock/+page.svelte**: → `EventLog.svelte`, `QueueTables.svelte`
  (активные+завершённые таблицы), `EnqueueForm.svelte`; у страницы остаются
  состояние, ws и поллинг (~200 строк).
- **widgets/roulette/+page.svelte**: визуальную сцену фаз (idle/spinning/completed)
  → `RouletteStage.svelte`; логика фаз и ws остаются в странице.
- **RulesSection / RaritiesCard / RouletteSlotsCard / ActionsSection** (общий паттерн
  «карточка = список + форма + логика»): формы → отдельные `*Form.svelte`,
  карточки остаются списками. AdminsCard — по факту аудита.
- Каждое разбиение — механический перенос шаблона+стилей, пропсы вниз, события вверх;
  поведение не меняется, проверяется svelte-check + глазами.

Порядок внутри шага: от самого крупного (dock) к меньшим; если очередное разбиение
начинает плодить prop-drilling — стоп, значит граница выбрана плохо.

## Шаг 9. Финальная проверка

```sh
pnpm --filter frontend lint && pnpm --filter frontend check
pnpm --filter frontend test:unit -- --run
pnpm exec prettier --check apps/frontend/src
```

Ручной визуальный smoke: админка (все страницы + светлая/тёмная тема), докпанель,
главная/stream/links, оверлей рулетки — сравнить до/после.

## Оценка

5–8 ч: консолидация стилей (шаги 1–6) ~2–3 ч, линт-обвязка ~1–1.5 ч,
разбиение компонентов ~1.5–2.5 ч, проверки и визуальный smoke ~0.5–1 ч.
