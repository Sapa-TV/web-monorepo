# SQLite-репозитории на sqlx вместо in-memory

Эпик: SAPATV-19. Статус: план согласован, к выполнению.

## Решения

- Миграции — `sqlx::migrate!`, по одной минимальной на шаг, сиды в своих
  миграциях; монолитного init-файла нет. Нормализация переводов строк идёт до
  sqlite-работы отдельным коммитом, иначе миграции хешируются нестабильно.
- Запросы: compile-time `query!`/`query_as!` для статических, runtime API —
  только для динамического SQL (keyset-пагинация с опциональными фильтрами).
  Офлайн-метаданные `.sqlx` коммитятся.
- Одна БД и для рантайма, и для компиляции макросов:
  `DATABASE_URL=sqlite:data/server.db?mode=rwc`. Свежий клон без `.env` уходит в
  офлайн на закоммиченном `.sqlx`, поэтому CI БД не поднимает.
- Поменял запрос или миграцию → `just sqlx-prepare` → коммит `.sqlx`.
- Схема: даты TEXT RFC3339, булевы INTEGER, JSON-колонки TEXT;
  `INTEGER PRIMARY KEY AUTOINCREMENT` только у генерируемых id, фиксированные PK
  — без автоинкремента; колонка триггера — `trigger_kind`.
- Старые юнит-тесты остаются на in-memory, паритет-сьюты гоняются против обеих
  реализаций. Тестовые БД — temp-файлы, не `:memory:`: пул даёт отдельную БД на
  каждый коннект.

## Что нельзя упростить

- `dequeue_next_with_slot` и `update_status_if` обязаны быть атомарными:
  check-then-act через несколько вызовов репозитория даёт гонку двух спинов и
  lost update. В SQLite каждый схлопывается в один стейтмент, поэтому сервисный
  слой и транзакции через несколько репозиториев не нужны.
- Приоритет Error→Pending — контракт трейта `QueueRepository` (rustdoc), а не
  деталь реализации: его соблюдают обе реализации, паритет-сьюты фиксируют
  исполнение.

## Осознанное расхождение с in-memory

FK с `ON DELETE CASCADE` (слоты при удалении rarity, `user_platforms`, правила
при удалении action) — желаемая семантика sqlite. In-memory сирот не чистит:
эмуляция каскада потребовала бы связки независимых репозиториев ради тестов, а
cleanup-on-read скрыл бы баги.

## Риски

- sqlx-cli и крейт одной версии (0.9.0), иначе метаданные несовместимы.
- cwd макросов — корень воркспейса, скрипт передаёт абсолютный путь к БД.
- `RETURNING` требует SQLite ≥ 3.35 (bundled-сборка подходит).
- `weight` u64 → i64 без паники: `i64::try_from` с
  `RepositoryError::Conflict("weight out of range")`.
- Кириллические сиды в миграциях — UTF-8 без BOM.
