# Задачи

## Баги, мелочи и UX

- [ ] док-панель рулетки: инпут добавить пользователя должен быть всегда
      открытым, по enter - добавить, очистить поле, чтобы можно было добавлять
      нескольких
- [ ] док-панель рулетки: надпись dequeue поменять - напискать "Крутить для:
      {username}", чтобы имя было прям в кнопке. в username добавить platform
- [ ] док-панель рулетки: кнопка прокрутки нужно сделать disabler если виджет
      оффлайн
- [ ] переделать дизайн рулетки, закрепить шрифты для виджетов - должны быть
      круглые милые шрифты
- [ ] Статус стрима по платформам: сейчас `StreamStatus` — один глобальный булев
      флаг, который докручивается вручную через `POST /wapi/stream`. Нужен
      статус по каждой платформе: для VK источник — поле `stream.status` из
      `GET /v1/channel` и события сокета `channel-info:{id}`
- [ ] Импорт заказов: опция матчить `customer_name` на
      `user_platforms.platform_username` (case-insensitive) и заполнять
      `user_id` при импорте из Google Sheets

## Сложные / несрочные

- [ ] Интеграция YouTube: ingress (чаты/события), авторизация канала, статусы
      стрима — по образцу twitch-платформы
- [ ] Донаты VK: в чат-пуше у сообщения есть признак доната/сумма — выяснить
      формат и маппить в событие, чтобы правила работали с донатами VK
- [ ] Чат на сайте: пользователь входит через Twitch (flow уже есть). Отдельно —
      чат на странице стрима вместо встроенного чата Twitch. Наш чат должен
      попадать в общий поток событий платформ. Когда дойдёт до VK — вход через
      VK ID (бэкенд-эндпоинта логина пока нет, фронт на
      `/login-callback/vk-video-live` показывает «пока недоступен»)
- [ ] Виджет-агрегатор чатов: собирает чаты со всех платформ (VK, YouTube,
      Twitch и наш сайтский чат) и показывает их в виде горизонтальной полосы на
      HTML-странице (тему для оформления найду)
- [ ] Подключение ODA — донатная платформа; документацию найду
- [ ] редактирование действий и правил надо переделать, сделать по аналогии со
      streamerbot (понадобится создать какую-то очередь супер-действий)
- [ ] Нормальная админка для управления наградами: видеть, создавать и
      редактировать награды за баллы канала прямо из панели, не заходя в Creator
      Dashboard (Twitch API: `POST /helix/channel_points/custom_rewards`, scope
      `channel:manage:redemptions`). Бонус: у наград, созданных приложением,
      появляется полное управление
- [ ] Автофулфилл редемпшенов как экшен движка правил. Ограничение Twitch:
      приложение может фулфиллить только те награды, которые само и создало (см.
      пункт про админку наград); к ручным наградам стримера доступа нет
- [ ] Правила/движок: Событийный поток наружу (WS/оверлей) — спроектировать
      отдельно от шины B, когда понадобится (напр., как новые экшены с
      собственной шиной; сейчас виджет уже читает очередь через `/wapi/queue`)
- [ ] Правила/движок: Новые матчеры и условия правил (кроме
      `MessageContains`/`RewardId`), кулдауны и лимиты на юзера, порог стоимости
      награды
- [ ] Правила/движок: Плагины экшенов без кода (скрипты/UI-редактор)
- [ ] Автоматизация справочника заказов (см.
      `docs/archive/plan-orders-directory.md`, раздел «Автоматизация»): новые
      экшены движка правил —
      `add_order_entry { list: games|movies, customer, source: 'roulette' }`
      создаёт запись с `title = NULL` по событию
      `PlatformEvent::reward_redemption`; `add_vip_record { kind: vip|unvip }`.
      Зависит от пунктов «Админка управления наградами» и «Новые матчеры/экшены»
